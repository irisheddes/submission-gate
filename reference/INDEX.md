# Index — the standard, by section

The auditor loads from here, one section at a time — `CLAUDE.md`, *The loading rule*.

Sections are the document's own, in its own order and with its own spelling (it prints
"ELEGIBLE" and "JURISDICITION"; both are left as published). Page markers `[pN]` inside each
file are PDF page numbers, inserted so any citation can be checked against
`rules-for-participation.pdf`: the first is the page the section starts on, each later one is
where that page begins.

**To find the exact stretch of text for a provision**, such as § III Art. 6.1 or
Annex 1 Art. 20.3(c), use `PROVISIONS.md`.

**This index is a navigation aid, never the authority.** A finding cites the section file, or
the PDF — never this page.

## What is stored, and what is not

**The whole document is stored** — all eleven sections, complete, plus the PDF as published.
Nothing was omitted, abridged or summarised.

**Not all of it is auditable**, which is a different question. `REQUIREMENTS.md` lists which
sections carry obligations on an *applicant* and which bind a *participant* after admission;
only the first can be checked against an application package.
